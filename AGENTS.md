# Weekly Agent Guide

## Project

Weekly is an Astro and Markdown static site for weekly posts.

Deploy surface: pushing `main` is production. Vercel builds and publishes `weekly.tw93.fun` automatically on every push; there is no staging.

## Repository Map

- `src/pages/posts/` - Chinese posts, one file per issue, named `{issue-number}-{Chinese-title}.md`.
- `src/pages/en/posts/` - English translations, matched to the Chinese post by issue number. English filenames zero-pad the number to three digits (`001-`); Chinese filenames pad to two (`01-`). The slug after the number differs.
- `src/` - Astro source, shared utilities, and page components.
- `public/` - static assets; `public/posts.json` is generated by `build.js`.
- `public/icon.svg` - the canonical coffee cup, shared by the inline page mark and the adaptive favicon. `pnpm brand:generate` exports the PNG/ICO icons; commit them with their source. The bilingual share images `public/og-zh.png` and `og-en.png` (1280 by 640) are the family share cards since 2026-10-30, made by Kata `scripts/share-cards/gen.py` with the other products' cards (潮流周刊 and Weekly in serif type beside the cup on an ivory disc, on deepened brown), so replace them from there.
- `README.md` post list, `RECENT.md`, `public/posts.json`, and `public/skills/weekly-issues/SKILL.md` - generated by `pnpm sync:content`; do not hand-edit. `build.js` writes the first three, then the Astro build provides the real `/api/posts.json` record used to render the Skill from `scripts/templates/weekly-issues.SKILL.md`.
- `public/styles/giscus-{light,dark,blog}.css` - the comment themes for Weekly and for tw93.fun, whose giscus include loads `https://weekly.tw93.fun/styles/giscus-blog.css`, so keep that path. `node scripts/generate-giscus-themes.js` renders all three from `scripts/templates/giscus-theme.css`; edit the template or its tokens, never the output. `/styles/` is cached for a day plus a week of stale-while-revalidate, so a blog theme change also needs the `?v=` in tw93.github.io's `_includes/giscus.html` set to the new commit. `tests/giscus-themes.test.js` fails on a hand edit.
- `scripts/` - maintenance scripts, including image probing and translation helpers.
- Machine-readable surfaces, all generated at build time from the same posts, never hand-edited:
  - `src/agents.ts` - issue metadata, Markdown twins (`/posts/{n}.md`, `/en/posts/{n}.md`), `/index.md`, `/en/index.md`, and the item index (`/api/items.jsonl`, `/api/en/items.jsonl`, `/items/{year}.md`, `/en/items/{year}.md`) built from `src/issueItems.js`, the dependency-free parser that splits an issue into its recommended items. Some English translations dropped an item's `<url>` line; the index borrows the link of the Chinese item that `alignTranslation` pairs it with, anchored on links both sides share, and leaves it empty when the pairing is ambiguous.
  - `src/agentGuide.ts` - `/llms.txt`, `/llms.md`, `/api/llms.txt`, `/posts/llms.txt`.
  - `src/pages/api/` - read-only JSON API; `src/pages/openapi.json.ts` describes it; `src/pages/feeds/posts.jsonl.ts` and `src/pages/schemamap.xml.ts` are the structured-data feeds.
  - `src/aboutMarkdown.ts` plus `src/data/about.*.md` and `src/data/faq.ts` - single source for `/about`, `/en/about` and their `.md` twins.
  - `public/.well-known/` - RFC 9727 API catalog and the Agent Skills index; `public/skills/` - published SKILL.md.
  - `vercel.json` - content types for `.md`/`.jsonl`/`api-catalog`, RFC 8288 `Link` headers, `/api` rewrite, `?mode=agent` redirect.
- `.github/workflows/verify.yml` - read-only `pnpm test` on pull requests and manual dispatch; it never commits.
- `.github/workflows/build.yml` - the main-only, daily and on-push content writer: translate missing posts, regenerate indexes and the public Skill from the built API, verify them, make one scoped commit, and ping IndexNow. It does not deploy the site; Vercel does.
- `api/` - the only server code: Vercel Functions for the email newsletter (`api/subscribe.js`, `api/confirm.js`, shared `api/_newsletter.js`; an underscore file is not deployed as a function). `scripts/newsletter.js` turns a published issue or blog post into an email, and `.github/workflows/newsletter.yml` sends it, manual dispatch only. See «Newsletter».

## Content Rules

- Frontmatter: `date` (format `YYYY/MM/DD`) is required; `image` is optional. The post title comes from the filename, not frontmatter.
- Chinese posts: `src/pages/posts/{issue-number}-{Chinese-title}.md`, number padded to two digits; English posts live in `src/pages/en/posts/` under the same issue number, padded to three. Do not mix languages in a single file.
- The site ships two language surfaces. Before changing any page-level metadata (share/OG title, description, social card), list both the Chinese and English copies plus the share-card fields, and sync all of them; the English site keeping a Chinese share title is the known failure this rule exists for.
- An issue description is the first `<small>` sentence, in that file's language. The about page's document title is its heading (`关于潮流周刊`, `About Weekly`). Do not lengthen titles or descriptions to satisfy a webmaster character count. `tests/seo-copy.test.js` checks both.
- Preserve the author's voice: do not make colloquial phrasing formal, do not add emoji unless the original has them.
- Inline media width is author-supplied and load-bearing: `rehype-image.js` re-emits the width written in the source for CDN-hosted images (stripping a `px` suffix) and passes SVG, GIF and non-CDN tags through untouched; it never rewrites `<video>` width at all, so CSS capping at the column is the only other constraint. New media follows the house pair: landscape fills the column as `<img ... width="800">` and `<video width="800px">`, portrait and phone screenshots halve to `400` and `400px`. The `px` suffix belongs on video only; images carry a bare number. Published issues carry a long tail of other widths, 500 and 600 most often; do not normalise them. Changing a width in a published issue means changing the Chinese and English twins in the same commit.
- Claims in the agent surfaces (`llms.txt`, `/llms.md`, `/about`, JSON-LD, SKILL.md, agent-skills index) must stay checkable against the repo: issue counts come from the post set, the first issue is 2020/11/24, and the site has no auth and no sandbox; its one write endpoint is the reader email signup at `/api/subscribe`. Do not advertise an endpoint, credential flow or MCP surface that does not exist.

## Working Rules

- Do not delete existing posts or rewrite old content unless the task explicitly asks for it.
- Let `pnpm sync:content` regenerate `README.md`, `RECENT.md`, `public/posts.json`, and the public Skill after content changes; do not edit them by hand.
- Translation automation writes missing English posts under `src/pages/en/posts/`; preserve Markdown and frontmatter shape.
- Issue identity is numeric: Chinese filenames use a two-digit minimum prefix, English filenames a three-digit minimum prefix. `pnpm check:content` rejects alternate spellings and duplicate numeric IDs.
- `.github/workflows/build.yml` is the single content writer: translate missing English posts, regenerate all indexes and the public Skill with `pnpm sync:content`, gate with `pnpm test:unit` and `pnpm check:content` (the same checks `pnpm test` runs), then make one scoped commit. Do not split those writes across independently triggered workflows.

## Type and Alignment

- Five text sizes, each with one job: 26 page titles and the logo title (issue title, about title, `.heti h1`), 20 `.heti h2`, 18 `.heti h3` / an entry's bold lead / the phone card title, 16 (`--font-size-base`) body, sidebar issue list, header links and the desktop card title, 14 (`--font-size-small`) dates, summaries, captions and buttons. Settled on 2026-10-29 from rendered before/after pages after the site had drifted to ten sizes (32 beside the 26 logo read as two systems). New text takes one of the five; a new size needs a stated reason. Left outside on purpose: `sup` 12, the search clear button 12, and the newsletter email input 16, below which iOS zooms the page.
- Styles nothing can produce are deleted, not kept for later: on 2026-10-29 a selector audit against all 1152 built pages and every script removed about 220 selectors (Heti's modifier and helper classes, highlight.js, mermaid, plantuml, markmap, MathJax and emoji rules, the old `.header-link` / `.sr-only` docs styles, lightense leftovers). Before deleting a selector its class or attribute is missing from, also search the scripts: reader mode sets `data-reader-mode` through `dataset.readerMode`, and PhotoSwipe builds `pswp__button--close`, `pswp__counter` and `pswp__preloader` from a name at runtime, so neither appears literally. `.heti` rules for elements Markdown can write (`h4` to `h6`, `sup`, `sub`, `figure`, `abbr`, `cite`, `ins`) stay even when no issue uses them yet. Prove a deletion with computed styles: dump every element's computed style on the home page, an issue, about and both English twins at 393, 1200 and 1440 in both themes, before and after, and expect no difference.
- The logo is the same in `Header.astro` and `LeftSidebar.astro` (40px cup pulled 14px up, 26px title 9px off it and raised 1px, which puts its ink 2px under the cup's centre: centred exactly, it read as sitting high beside the cup's lighter body, maintainer 2026-10-30), so going from the home page to an issue the cup does not move; change both together. The header's right-hand row is pulled up 3px (`.header-right`, halved by the flex centring) and `HeaderLink` keeps 1px of top padding, which puts the links and the round buttons on the logo title's line; on an issue page `#grid-main`'s 16px top padding puts the issue title and its buttons on the same line (maintainer 2026-10-30: the logo title, issue title and buttons share one centre line). Breakpoints written as `max-width` use 799.98px, since `max-width: 800px` and `min-width: 800px` both matched at exactly 800 and that width got the phone padding. Sidebar issue rows are 6px above and below, about a 38px pitch (tightened from 8px on 2026-10-31, maintainer: the rows read too loose); the desktop `.nav-groups` top margin cancels that padding, so change the two together.
- Audit sizes from what renders, not from the CSS: walk every visible text node on the home page, an issue, about and an English issue at 393 and 1440 and list size, weight and container. Then fold, inject the candidate on the live pages, and compare before/after captures.
- Align by ink, not boxes. Capture each element alone (hide the rest with `visibility`) and compare the vertical centres of the inked rows across 393 to 1920 in both languages; measure English links on words without descenders, since the `y` of "Weekly" pulls its centre about 3px low. Two things corrupt the numbers: a browser page zoom other than 100% (ego was at 110%, so a 1024px emulation laid out at 931 and captures no longer matched DOM coordinates), and the service worker, which also caches `astro preview` on localhost, so unregister it and clear its caches before measuring a local build.
- Signed-in comment states cannot be styled from here: the giscus iframe is cross-origin, and a `session` from its URL must never be reused. Rebuild that markup from giscus `components/CommentBox.tsx` inside the standalone widget page, inject the generated theme, and measure it there; check the live signed-in page by eye afterwards.

## Verification

- Brand changes: retain the cup and sleeve colour, verify both explicit page themes and the favicon's system theme, inspect 16px and 32px exports, and keep the complete desktop icon inside the maskable centre circle. Check the Chinese and English generic share images separately; published per-issue covers retain their own artwork. Wait for colour transitions to finish before measuring or capturing theme changes.
- Site or content changes: run `pnpm build`. For image-processing, translation, frontmatter, Markdown tables, video, horizontal layout, or viewport-triggered behavior, also run `pnpm dev` and inspect the actual affected posts yourself; a green build does not mean the page still looks or behaves right, and push is production. Check the Chinese and English twins when both exist, plus user-visible feedback (media playback, table headers/scroll, toast, copy-success message, share title) at a mobile width and a desktop width; a desktop-only or source-only pass is not runtime proof.
- Image-related changes: run `pnpm image:probe` or rely on the `prebuild` step.
- Translation changes: verify `GROK_API_KEY` is provided before running `scripts/translate_posts.js`, then inspect generated English Markdown before committing.
- Content/index changes: run `pnpm test`; it checks bilingual issue parity, canonical filename prefixes, `public/posts.json`, and the generated public Skill.

## GitHub Operations

- Use `gh` for issue and PR inspection.
- Do not post public comments unless the maintainer explicitly asks.
- Draft public replies in the same language as the thread.
- Each published issue gets a GitHub Discussion titled with its number (issue 286 is discussion #322). After publishing an issue, react to it as `tw93` with the six positive reactions, THUMBS_UP, LAUGH, HOORAY, HEART, ROCKET and EYES; never THUMBS_DOWN or CONFUSED.

## Telegram Channel

- Each issue is also announced in the Telegram channel 「Newlearnerの自留地」 (@NewlearnerChannel) through AyuGram. The agent only fills in the cover and caption in the send dialog, then stops; the maintainer clicks Send or right-clicks it to schedule. The agent never clicks Send, Schedule or any menu item there, because a misclick posts to the whole channel at once.

## Newsletter

Readers of the Weekly and of tw93.fun subscribe by email through Resend, sent from `Tw93 <hi@tw93.fun>`. Safety rules, each covered by `tests/newsletter.test.js`:

- Double opt-in, stateless: `/api/subscribe` only mails an HMAC-signed confirmation link (valid two to three days), and only the POST behind the button on `/api/confirm` writes the contact; a GET never writes, because mail scanners open every link. The same request on the same day reuses one Resend idempotency key, so repeated submissions mail one confirmation.
- `/api/subscribe` accepts only `Origin` `https://weekly.tw93.fun` and `https://tw93.fun` (the blog form posts here cross-origin), drops honeypot submissions, and answers 503 when any setting is missing rather than half-working.
- Resend keys live only in Vercel and GitHub secrets: Vercel needs `RESEND_API_KEY`, `NEWSLETTER_SECRET` (32+ characters), `RESEND_SEGMENT_ZH`, `RESEND_SEGMENT_EN`, `RESEND_TOPIC_WEEKLY`, `RESEND_TOPIC_BLOG`; the workflow needs the same minus the secret, plus `NEWSLETTER_TEST_TO`. Segments split by language, topics by site, and both topics were created with default Opt-in. New contacts must explicitly opt out of unselected topics; existing contacts keep their other choices. Duplicate detection checks both the requested topics and the language segment.
- The form renders only when the Vercel build sets `PUBLIC_NEWSLETTER=1`. Turn it on only after a real signup, confirm and test send went through, and in the same change replace the FAQ line that says there is no mailing list.
- Sending is never automatic: run the workflow with `mode: test`, read the email, then `mode: send`. `send` refuses a post whose Broadcast name (`weekly-zh-287`) already exists.
