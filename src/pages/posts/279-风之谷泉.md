## 潮流工具

**Cumora：这个很不错的 Agent 团队协作工具居然开源了**
<https://github.com/yetone/cumora>
来自 yetone，又是一个「没有想到」系列，居然开源了。在目前的开源方案里，这应该是我看过做得很不错的 Agent 团队协作工具，客户端本身很完整，代码的处理也很值得学习。

**Omarchy：最近很火的漂亮且现代的 Linux 系统**
<https://omarchy.org/>
Omarchy 是一个基于 Arch 的 omakase Linux 发行版，采用平铺式窗口管理器 Hyprland 和桌面构建工具包 Quickshell，预装了不少 AI 时代生产力工作需要的工具，好评挺多的，有空闲机器的小伙伴可以去试试看。

**MicroLighter：一个非常小的代码语法高亮库**
<https://davatron5000.github.io/microlighter/>
居然 gzip 后才 2.05 KB，用起来看着也很简单。不过我让我的 Agent 判断了一下，是否可以替换潮流周刊的语法高亮库，被婉拒了，哈哈。假如你在做新项目，可以试试看。

**iGhostty：越狱 iPhone 上的命令行终端**
<https://github.com/OwnGoalStudio/iGhostty>

**随便写写：我是如何给产品取名字的**
突然想跟大伙聊聊，我是怎么给自己的产品取名字的，这个过程很有趣，或许你也可以结合自己的性格和喜好，给产品取一个不错的名字。

在 AI 还没来之前，市面上各种 Coding 产物没有这么多，我很看重产品本身的生命感和存在感，所以基本都会非常认真地对待取名这件事。好比一个新生儿出生，父母需要花不少时间，给这个即将到来的生命取一个陪伴她一辈子的名字，让她以后也很喜欢自己的名字，甚至能从中获得一生的鼓励和自信。

即使在 AI Coding 产物盛行的这一代，假如你想把产品推向大众，而不只是自己把玩，我还是非常推荐你给她取一个好名字。这样每次向大众介绍的时候，你也会对自己的产品很自信、很喜欢，愿意花时间和精力把她持续迭代好。

我的第一个产品叫做妙言，是在 2020 年前后做的。那时候 Markdown 笔记应用非常火，我感觉没有太顺手的，就自己学 Swift 写了一个。我特别喜欢中文字，当时也没有考虑国际化，更多是自己用，记录工作学习中的各种笔记。我一直认为好的文字是有生命力的，于是想到了「妙不可言」，正好是写文字时想表达的感觉。现在我依然很喜欢这个名字，也一直在迭代，读起来朗朗上口，简单好记。这里想表达的是，产品名字需要和产品本身的功能，或者它想体现的意义有关。假如取了一个不相关的名字，虽然好听，你也不太好讲。

第二个产品叫做 Pake，是一个用 Rust 写的、可以一条命令把网页打包成轻量桌面应用的工具。为什么这次开始取英文名？后来我发现妙言在国外用的人也很多，直接用 MiaoYan 这个拼音去介绍很奇怪，所以后面的产品，我尽量取一个大家多少都能看懂的名字。当时给 Pake 取名，我想到的是「打包」这两个字，换成英文是 Pack，这个词其实挺好，但太大众了。现在回想起来，这里的灵感和 Vue 很像：Vue 最开始应该是想叫 View，但尤大觉得这个名字太直接，就放到谷歌翻译里试，找到了它的法语翻译 Vue。我给 Pake 取名时也是这样，去找「打包」在各种语言里的翻译，最后发现在海地克里奥尔语里，打包就叫 Pake，狂喜，就取成这个了。而且这个名字很好拼写、好记、好打字，任何人用过之后应该都能记住，同时 Pake 自己的命令也是 `pake`，这样产品的使用和传播就很简单了。

第三个产品就是我们更熟悉的 Mole 了，当时还是一个深度挖掘你 Mac 电脑垃圾的命令行工具。这次我是先取的中文名字，我一直把这个产品当做一个有动作、看似安静、勤恳清理垃圾的小可爱，当时就在想，什么小动物最贴合这种感觉，想了很久都没想到喜欢的。好像是在一本小孩的书上看到介绍鼹鼠，突然一想，对对对，就是我想要的，安静、小、疯狂挖掘。更惊喜的是，英文名 Mole 非常贴合我一贯的取名风格，好记、好写、好读，但不大众化，现在回忆起来很有意思，挺好玩的。

后面 3 个产品被我不经意间做成了一个系列，那就是 Kaku、Waza、Kami。应该说，没有 Kaku 的取名，就没有后面这两个产品的名字。Kaku 是我去年春节长假写的一个轻量、简单、零配置上手、AI 友好的命令行终端工具，取名的时候我唯一想到的，就是这个产品一定要表达出轻快、很爽的感觉。然后我开始随口乱念不同的词，最后最后，发现 kaku kaku kaku 念起来非常爽，就按照这个音去找，发现 kaku 是日语里「書く」这个词，意思是书写。太有意思了，终端和书写的关系很近，而且很有诗意，它还是《海贼王》里的一个角色，立马就取了这个名字。后面的 Waza 是日语的「技」，对应我做的工程师 Skills，也很贴合。Kami 是「紙」，是我那套「好内容值得好版面」的排版 Skills 的名字，正是我想表达的意思，纸面是干净的，可以写出很多有价值的东西。

并不是说名字对产品至关重要。比如 Anthropic 刚出来的时候，我非常讨厌这个名字，因为永远记不住怎么拼，但也不妨碍它的产品和模型成功，没有什么必然关系。即使你的产品叫做二狗，只要非常牛逼，也不妨碍它成功。不过有些名字还是会带来影响，比如还有一个丑名字叫做 Antigravity，甚至比 Anthropic 更难读难写。其实从它刚刚推出时，我就有点儿感觉这个产品很难成功，因为本身模型并非第一第二，只能更多靠产品能力来拼，结果产品能力也不太好，就变成现在这样了。此外，也不是名字短、看着简单就好。比如 Trae，我到今天还是很容易打成 trea，或者忘记怎么打，可见名字短、字母简单不等于好名字，它不好记、不好拼，看起来也没什么含义。假如他不告诉你这是 The Real AI Engineer 的缩写，可能永远不会有人知道，这样就比较难在大众市场打开。

一不小心就碎碎念了这么多，比较想表达的就是，产品应该有自己的调性和性格，不能千篇一律。当然，我说的取名方法更适合我自己，适合我的性格。对你而言，产品也需要贴合你的性格和喜好，比如你喜欢日本动漫，就可以多往里面的角色靠近，你喜欢中国古代神话，也可以从里面找一些稀有但有趣的名字。最后最后，我认为名字一定要朗朗上口、好读、好记、好写，不长，甚至在键盘上敲起来很无感。
