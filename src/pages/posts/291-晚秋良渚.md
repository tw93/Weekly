**吉隆坡游记记录一下看到的不一样的东西**

<video poster="https://weekly.tw93.fun/assets/posters/a9eb0f61f219.v2.webp" width="800px" preload="metadata" controls><source src="https://cdn.tw93.fun/notes/13_2124366670596857856.mp4" type="video/mp4"></video>

每次出国旅行回来，我都想着写一个文章，来和大伙聊聊我实际看到的和原本想象到的不一样的地方，非常有意思，或许这就是旅行的意义，刚好还没有忘记，来给大伙聊聊这次我去马来西亚吉隆坡看到的不一样的事情。

1. 吉隆坡比我想象中要发达不少，发展有点儿像中国的广州，甚至在核心地段会有一种上海的感觉，但是生活上又很像重庆，本地人不紧不慢，同时地理和重庆也很像，很多时候路上进去直接就是这个楼的三楼。

2. 油车非常多，电动车非常少，和本地朋友了解到马来西亚的油价只有国内的 1/3，所以路上几乎都是油车，因为花费非常便宜，开电动车类似特斯拉这种的一般是科技新贵，那几天我没有看到一辆特斯拉，甚至比亚迪电车在那边都属于挺不错的车。

3. 由于水电能源丰富，有不少全球科技中心会在周边建立数据中心，比如 AWS、微软、谷歌他们都在这边有非常大的数据中心，互联网和科技公司，去东南亚一般会用的 Grab 打车起源这里，谷歌、微软、亚马逊、Shopee、Lazada、支付宝也有办公地在这儿，基本都在非常高级的地方。

4. 聊到打车软件 Grab，油价虽然便宜，但是这儿的人工成本我感觉比国内要贵不少，打车的价格和上海差不多了，但是车的品质可能还会差一点，Grab 在那边会有点儿像滴滴+美团外卖的这种结合体，甚至打车推荐你用支付宝里面的 Grab 会给你推荐华人司机，此外这边本地人骑摩托车的非常多，经常在高速路上看到不少飞快的摩托车少年，下大雨也有不少人骑，可能就是自己的出行工具来。

5. 吉隆坡的天气很有意思，出发前，看天气预报是高温暴雨，结果这里的暴雨那几天属于很短时间就停了，但是雨特别大，雨停以后，非常舒服凉快，出太阳的时候很热，现在有点儿像杭州的夏天，但是这边商场这种室内空调开得非常足，了解到马来西亚就两个季节，旱季和雨季，刚好这段时间属于雨季。

6. 吉隆坡的外国人比我想的要多不少，马来本地人、华人、印度人、欧美、日韩不少，马来语很像英语，不过本地语言还是需要翻译软件，好在不少店铺都有华人，中文交流完全没有问题，不过英语好的话在这儿生活完全没有问题的。

7. 聊到马来本地人，政府给到的福利其实很不错，所有政府公共机构，类似我们公务员的职位全部只能本地人去申请，所以在很多公共部门可以看到不少本地偏信伊斯兰教的员工，华人和国外人一般在吉隆坡基本做生意类的，相比本地人会努力很多。

8. 去吉隆坡由于免签，非常方便，然后我担心在需要现金在机场还兑换了 600 马币，后面才发现亏了，过去旅游我感觉几乎不要兑钱，反而汇率还吃亏，完全支付宝可以很好搞定，甚至很多地方吃饭还不支持现金，有支付宝微信完全够用了。

9. 生活习惯上，本地的生活节奏非常慢，时间也很宽松，这边非常喜欢吃甜的，国内的奶茶店不少，本土也有不少奶茶、冰淇淋店，我感觉甚至有点过甜了，然后车靠左行驶，方向盘在右边和国内反的，然后过马路得先看右边开始还有点不习惯。

10. 本地的华人非常热情，很和蔼，当时看完李志演唱会，打了一个 Grab，是一个华人老爷爷接的，非常耐心给我拍照车在哪儿，等了挺久，非常耐心下车等，包括去餐厅点菜是华人的都很客气。

11. 然后给大伙推荐一波过去的住和吃，住的地方推荐武吉免登或 KLCC，我这次住在武吉免登这边的万豪，这两个地方很近，完全可以步行去旁边的柏威年广场逛街吃饭购物，在 KLCC 这边去双子塔就在旁边，以及 Suria KLCC，就在双子塔脚下的购物中心也非常大和好逛。

12. 吃的这边比较丰富，不过我感觉米没有国内的好吃，推荐吃这边的面，非常推荐 Mama Lek，很好吃，然后这边牛肉面也还不错，西餐也还可以，想吃饭可以去试试椰浆饭配一个大烤鸡腿也好吃，Thong Bowl 吃了一个面太辣了，一定要记得吃不了辣点微辣，我居然在这里吃了 2 个中国这边的饼，商场负一楼的牛肉饼和鸡肉饼非常好吃，笑死我了。此外这边咖啡不错，一定要找几个地方喝喝咖啡，挺舒服的。

13. 景点的地方，推荐去独立广场看看，比较庄严的一个地方，应该是马来西亚国旗第一次升起的地方，不过游客可以上去，到处拍照，里面也有不少西餐咖啡厅，整体拍照我感觉很好看，下图就是，然后推荐去 KLCC 双子塔看看，那边有一个无边泳池，可以约着去游一个泳。然后我感觉找一个天气凉快的早上，在吉隆坡找一个人少的地方散步还是很舒服的。

**我是怎么把电脑和手机搭建成一个非常好用 Agent 工作开发环境的**

突然很想给大伙分享一下，我是怎么把家里的旧电脑旧手机和我的主力 Mac 搭建成一个非常好用 Agent 工作开发环境。

换在去年，强迫症的我可能这些旧设备全部被我闲鱼出掉了，只留一台主力 Mac，恰逢今年开发的软件有 Mac、Windows、Linux、iPhone 后，这些设备给我帮助非常多。

设备介绍

主力机是一台黑色 Mac M5 Pro 48 GB 内存 1 T 版本，非常好用，今年购买，唯一后悔就是当时应该买 2T 版本的，写代码、签名公证、发版都在这个上面，也是我自己唯一使用的一台机器。

测试机是一台 M2 Pro 32 GB 内存 512G 的机器，是我买 M5 之前一直在用的一台，后面放到了柜子里吃灰了几个月，刚好 10 月份在弄 Mole 的软件的测试，需要 Agent 帮我做大量的电脑操作工作，原先在主力机上，好比有一个人在抢我电脑的感觉，终于受不了了，把所有的测试工作全部让 Agent 迁移到了这台机器。

然后这台 M2 测试机上，还插了我一台 iPhone SE3，使用 iPhone Use 和镜像可以让 AI 非常好的去操作它，它主要承担妙言 iOS 版本的测试工作，以及新产品的一些各种手机测试，这里 Agent 还可以通过 WebDriverAgent 把手机屏幕读成一个个元素，再按标签去点，非常好用。

不仅仅，这台测试机几乎被我利用到顶了，上面还用 Parallels 跑着一台 Windows 11 的 ARM 虚拟机，Mole for Windows 的 ARM64 版本就在这里测试的。

然后还有一台 Windows ThinkPad X1 8 GB 内存，当时为了写 Mole Windows 时候去整的，拿来测真实的 x64 硬件，屏幕缩放、电池、SmartScreen 和 Defender 这些虚拟机里看不到的东西，包括 Windows 版本的发版验收都需要这台真实的 Windows 机器。

为了更好利用到这台机器，我在它里面还安装了 Omarchy 的 Linux 虚拟机，用来测 Pake 在 Wayland 桌面上的表现，由于只有 8G，我尽量会让 Agent 一次任务只使用一个系统。

最后还有一台 NAS 微主机，上面跑着一个 Debian 12 的容器，x86_64 8 核 31 GB，专门来跑 Linux 命令行、GNU 工具的差异和 Pake 的 deb、rpm 打包，Mac 上的 BSD sed 和 Linux 上的 GNU sed 很多写法不一样，都用这一台机器来兜底。

我是怎么用它们来帮我测试的？

还是强迫症不想让书桌有这么多东西，我把这些测试机器全部放到了次卧里柜子里去了，所有设备插好电，做好通风，然后设置屏幕亮度最低，设成了永不睡眠也不黑屏，不过我会隔半个月去把这些机器全部重启一下。

首先我用他们来给我测试我的各种软件，我一直认为不管在什么时候，软件的发布应该是正式的，发布出来应该是稳定的，所以每次发布我会花费非常多的时间来自己测试，包括在自测之前会让 Agent 在真实的各种环境的机器上严格全部跑一遍，没有问题后，我再手工测试一遍，这样可以确保交到大伙手上的软件质量是过关的。

为了防止 Agent 测界面的时候在我主力机上和我抢鼠标的问题，一旦它动鼠标、抢焦点、切窗口的时候，我就没法用电脑，很别扭，所以才有了上面的多设备组网，在 10 月底我把所有要控制鼠标的活全部挪到了测试机上，UI 测试、端到端测试、点系统授权弹窗，都在测试机器上做，主力机只负责构建，然后把包发过去。

Agent 在测试机上操作并不是靠截图猜点击位置的，用的是自己写的两个很小的命令行工具，ax 走 macOS 的辅助功能接口，类似 ax tree <pid>，可以把一个 App 窗口里的每个元素连同标识、文字和中心点坐标打成文本，然后可以很好的按标识去按按钮，也很准确，然后 input 用 CGEvent 发鼠标和键盘事件，专门处理辅助功能树按不到的东西，比如右键菜单、往搜索框里打字、按 Esc 关掉菜单。相当于测试机上的内容被我转换成了 Agent 更易于了解的文本上下文，只有在实在解决不了的时候才截图来看，其他时候都用这种方法会快很多。

我是怎么用他们帮我来省钱的？

最近 3 个月，我的 GitHub Action CI 的费用超了非常多，几乎每个月差不多 70 刀往上，有点肉疼了，当时给大伙发过一次如何提高在 GitHub Action 上 CI 的效率和成本，但是还是不彻底，因为对于私有仓库 GitHub 托管的 macOS runner 是按十倍分钟计费，原生构建和测试特别烧钱。

于是我在 11 月初，在测试机上给我那几个私有仓库里各挂了一个自托管的 runner，比如 Mole Mac 的 make verify 跑一次得 20 多分钟，以及 Pake 跑 Mac 的测试也不快，还有妙言的 iOS 构建等等，全部迁移到本地测试机器上进行，当前这台 M2 测试机一共接了我将近 180 个 job，原来要花钱的地方由本地来承担了。

这里为了更加节约效率，我还做了一个检查机制，先在 Ubuntu 上跑一个只要几秒钟的小 job，去 GitHub 问一下当前主分支这个提交有没有已经跑完的完整测试，有就直接结束，没有才把活派给测试机。

不过这里有一个小坑，就是 CI 和 Agent 其实也在用一块屏幕，两边需要相互让着，我给做了一个「正在干活」的标记文件，Agent 每次通过脚本操作测试机，都会刷新这个文件，以及会区分是什么项目在用，比如 CI job 开始时先抢一个「CI 忙」的标记，用 noclobber 来创建，这样同一时刻只有一个能抢到，然后这里也有重试机制包括超时机制方便测试机可以在 24 小时不间断干活。

然后对于 Agent 也会相互抢同一块屏幕，好在现在各个对话之间可以相互发消息，要用的时候，先检查有没有人在用，再用的时候对方会问一下大概什么时候释放，然后另外一个 Agent 就很老实等着快到时候的时候才去检查，等等，类似这些里面有非常多的小巧思很有意思，所以现在阻碍我测试效率的应该是机器还是太少了，哈哈，不够也够了。

这样的好处还有什么？

回到昨天我发的那个，我说这次出远门，甚至都没有带主力机，就拿了一个家人非常轻的 Air 完全够用，甚至我感觉远比带上主力机还要方便太多了，假如带上主力机，其实在路上、飞机上这种移动位置，机器都是关的，啥事情也做不了，而且还容易更换国家位置导致 Claude 的一些不稳定，现在好比这些机器 24 小时都开着，一直在干活，一直在运转，反而现在卡点不在机器，而在我自己的注意力。

不过我还是感觉做这些最终最终，应该是为了让我更轻松，效率更高，有更多时间去做自己想做的事情，而非全部 full time 扑到上面，其实就有点本末倒置了，非常推荐大伙提高效率，留出时间来，做更多自己想做的非电脑干活的事情，这样生活才更有意思。

身体健康 > 生活快乐 > 码代码快乐，虽然都非常重要，但是还是要有优先级，这样才有精力去追求一些代码之外的有意思的东西。
